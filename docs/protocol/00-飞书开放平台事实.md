# 飞书开放平台事实（自建应用机器人）

本目录只记录**外部事实**：接口、字段、限额、平台行为。事实变了直接改本文件，不另立决策记录。调研日期 2026-11-19，出处均为官方文档；查不到官方数字的地方明确写「未查到官方数字」，不写经验值冒充事实。

## 1. 接收消息：事件订阅与长连接

- 两种订阅方式：**长连接（WebSocket，SDK 内能力）** 与 **Webhook（回调发到公网地址）**。长连接仅支持**企业自建应用**。来源：[使用长连接接收事件](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case)。
- 长连接限制（官方逐条）：
  - 收到消息后需 **3 秒内处理完成且不抛异常**，否则触发超时重推；
  - **每个应用最多 50 个连接**（每初始化一个 client 即一个连接）；
  - 推送为**集群模式，不广播**：同一应用多个客户端只有随机一个收到消息。
- 超时重推按 15 秒、5 分钟、1 小时、6 小时最多重试 4 次；链路内部重发会造成**重复投递**。
- 事件类型 `im.message.receive_v1`（接收消息 v2.0）。官方明确：**幂等请用 `message_id` 去重，不要依赖 `event_id`**。来源：[接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)。
- 事件 payload 关键字段：
  - `header`：`event_id`、`event_type`、`create_time`（毫秒）、`token`、`app_id`、`tenant_key`；
  - `event.sender.sender_id`：`open_id` / `union_id` / `user_id`（`user_id` 需字段权限才返回）、`sender_type`（`user` / `bot`）；
  - `event.message`：`message_id`、`root_id`、`parent_id`（回复场景，构成消息树）、`create_time`、`chat_id`、`thread_id`、`chat_type`（`p2p` / `group`）、`message_type`、`content`（JSON 字符串）、`mentions[]`（`key` 形如 `@_user_1`、`id`、`mentioned_type`、`name`）。
- **能收到什么由权限决定**（同一事件按权限分流）：
  - 单聊：`im:message.p2p_msg` / `im:message.p2p_msg:readonly`；
  - 群内 @机器人：`im:message.group_at_msg:readonly`（仅用户）或 `im:message.group_at_msg.include_bot:readonly`（含其他机器人）；
  - 群内全部消息：`im:message.group_msg`（敏感权限）或 `im:message.group_msg.include_bot:read`。
- 消息内容结构（`content` 各 `msg_type` 的 JSON 形状）：[接收消息内容结构](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/im-v1/message/events/message_content)。要点：
  - `text`：`{"text":"..."}`；@ 表现为 `@_user_1` 占位符，实际身份在 `mentions`；超链接是 `[文本](url)`；
  - `post` 富文本：`content` 为标签数组（`text` / `a` / `at` / `img` / `media` / `emotion` / `code_block` / `hr`），`content_v2` 中含 `md` 标签可保留原始 Markdown；
  - `image`：`{"image_key":"img_..."}`；`file`：`{"file_key":"...","file_name":"..."}`；
  - `interactive` 卡片：接收到的结构与发送时的原始卡片 JSON **不一致**（除非查询接口带 `card_msg_content_type=user_card_content`）。

## 2. 发送 / 回复

- 发送：`POST /open-apis/im/v1/messages?receive_id_type=<type>`，`receive_id_type` ∈ `open_id` / `union_id` / `user_id` / `email` / `chat_id`；请求体 `receive_id`、`msg_type`、`content`（**JSON 序列化后的字符串**）、`uuid`（去重：相同 uuid **1 小时内至多成功 1 条**，≤50 字符）。来源：[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)。
- 回复：`POST /open-apis/im/v1/messages/:message_id/reply`，支持 `reply_in_thread`；同样支持 `uuid` 去重。来源：[回复消息](https://open.feishu.cn/document/server-docs/im/v1/message/reply)。
- 消息类型：`text` / `post` / `image` / `file` / `audio` / `media` / `sticker` / `interactive` / `share_chat` / `share_user` / `system`。
- 体积上限：**文本请求体 ≤ 150 KB；卡片、富文本 ≤ 30 KB**（超限错误码 230025）。
- 发送前提：开启机器人能力（**开启后需发布版本才生效**）、目标用户在可用范围内、机器人在目标群中且有发言权限。
- @ 语法（[机器人 FAQ](https://open.feishu.cn/document/faq/bot)）：
  - `text`：`<at user_id="ou_xxx">名字</at>`，@所有人 `<at user_id="all">所有人</at>`；
  - 卡片 markdown 内：`<at id=ou_xxx></at>`、`<at id=all></at>`。

## 3. 编辑、撤回、已读

- **编辑**（`PATCH /open-apis/im/v1/messages/:message_id`）：仅支持 `text`、`post`；一条消息**最多编辑 20 次**；只能编辑自己发的消息；时限由企业管理员配置（帮助中心口径默认 24 小时）。来源：[编辑消息](https://open.feishu.cn/document/server-docs/im-v1/message/update)。
- **卡片更新**（同为 `PATCH /open-apis/im/v1/messages/:message_id`，仅 `interactive`）：仅 **14 天内**发送的卡片；**单条消息 5 QPS**；卡片 `config` 需显式 `"update_multi": true`；不支持批量发送与「仅特定人可见」的卡片。来源：[更新已发送的消息卡片](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/patch)。
- **撤回**（`DELETE /open-apis/im/v1/messages/:message_id`）：机器人只能撤回**自己发送的**消息，时限受管理员配置（帮助中心口径默认 24 小时）；机器人需仍在会话内。来源：[撤回消息](https://open.feishu.cn/document/server-docs/im-v1/message/delete)。
- **已读**：事件 `im.message.message_read_v1`（用户读了机器人单聊消息）；查询 `GET /messages/:message_id/read_users`（仅机器人自己发的、7 天内）。**未查到官方「把收到的消息标记为已读」的接口**。

## 4. 媒体

- 上传图片 `POST /open-apis/im/v1/images`：≤ **10 MB**、不接受 0 字节；JPG/JPEG/PNG/WEBP/GIF/BMP/ICO/TIFF/HEIC（TIFF、HEIC 转 JPG）；GIF ≤ 2000×2000，其他 ≤ 12000×12000。返回 `image_key`。来源：[上传图片](https://open.feishu.cn/document/server-docs/im-v1/image/create)。
- 上传文件 `POST /open-apis/im/v1/files`：≤ **30 MB**、不允许空文件；`file_type` ∈ `opus` / `mp4` / `pdf` / `doc` / `xls` / `ppt` / `stream`。返回 `file_key`。来源：[上传文件](https://open.feishu.cn/document/server-docs/im-v1/file/create)。
- 下载消息资源 `GET /open-apis/im/v1/messages/:message_id/resources/:file_key`：返回二进制流；`type=file` 未分片仅支持 **< 100 MB**，≥100 MB 需 `Range` 分片且单次 ≤ 32 MB；`type=image` 不支持 Range、仅完整下载 < 100 MB；**不支持表情包资源**；要求机器人与消息在同一会话。来源：[获取消息中的资源文件](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message-resource/get)。
- 机器人只能发**自己上传**的资源（错误码 230017/230055）；云文档的 `file_token` 不能当 `file_key` 用。

## 5. 交互卡片

- **卡片 JSON 2.0**：需声明 `"schema":"2.0"`；一张卡片最多 **200 个组件/元素**；**仅支持共享卡片**（`update_multi` 只能为 true）；`config.streaming_mode` 支持流式更新。来源：[卡片 JSON 2.0 结构](https://open.feishu.cn/document/feishu-cards/card-json-v2-structure)。
- **markdown 组件**：JSON 2.0 支持除 SetextHeading、CodeBlock、HTMLBlock 外几乎所有标准 Markdown（[富文本组件](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/rich-text)另列了代码块语法的适用条件与客户端版本要求）——**代码块与部分构造的真机表现列入验收清单**。
- **卡片回传交互** `card.action.trigger`（新版）：自建与商店应用均支持；服务端需 **3 秒内响应**（Toast / 更新卡片 / 不更新）；可在开发者后台选择**长连接**接收（旧版 `card.action.trigger_v1` 不支持长连接）。回传 `value` 需为**对象**（SDK 仅支持对象类型回传参数）。来源：[卡片回传交互回调](https://open.feishu.cn/document/feishu-cards/card-callback-communication)、[处理卡片回调](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/handle-card-callbacks)。
- 卡片延时更新 `POST /open-apis/interactive/v1/card/update`：用回调响应里的 `token`，**30 分钟内有效、同一 token 最多用 2 次**，卡片 ≤ 30 KB。来源：[延时更新消息卡片](https://open.feishu.cn/document/server-docs/im-v1/message-card/delay-update-message-card)。
- 流式更新：卡片级/组件级 OpenAPI **10 次/秒**。来源：[流式更新卡片](https://open.feishu.cn/document/cardkit-v1/streaming-updates-openapi-overview)。

## 6. 频控（官方数字）

来源：[频控策略](https://open.feishu.cn/document/server-docs/api-call-guide/server-api-rate-limit/frequency-limit)、[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply)。

- 超限返回 HTTP **429**（部分旧接口 400），错误码 `99991400` / `230020`；响应头 `x-ogw-ratelimit-limit`、`x-ogw-ratelimit-reset` 给出恢复秒数，按它等待重试。
- 频控按 每个 API × 每个应用 × 每个租户 计。
- 发送/回复消息接口级：**1000 次/分钟、50 次/秒**。
- **业务级：向同一用户发送 5 QPS；向同一群组发送为群内机器人共享 5 QPS。**
- 卡片：单条消息卡片更新 5 QPS；单卡片实体 OpenAPI 10 次/秒。
- **每日条数上限：未查到官方数字。**（不写经验值。）
- 官方不支持自助提频，消息场景不支持提频。

## 7. 权限与发布

- 发消息（应用身份，任一）：`im:message` / `im:message:send_as_bot` / `im:message:send`。
- 接收消息事件（任一，决定推送范围）：见 §1 分流表。
- 其他常用：撤回 `im:message:recall`；更新消息 `im:message:update`；资源上传 `im:resource`；历史消息 `im:message:readonly`（群聊另需 `im:message.group_msg`）；群管理 `im:chat` 系列。
- **机器人能力、事件、权限、可用范围的变更都要创建版本并发布后才生效**（测试版应用除外）。来源：[配置应用可用范围](https://open.feishu.cn/document/home/introduction-to-scope-and-authorization/availability)、[事件概述](https://open.feishu.cn/document/ukTMukTMukTM/uUTNz4SN1MjL1UzM)。
- 事件与回调的订阅方式在「事件与回调」页配置，**需先用 SDK 建立长连接在线才能保存「使用长连接」方式**；卡片回调在「回调配置」页添加 `card.action.trigger`。

## 8. Node.js 官方 SDK

- `@larksuiteoapi/node-sdk`，npm 最新 **1.76.0**（2026-10-16 发布），仓库 `github.com/larksuite/node-sdk`；依赖 `ws`、`axios`、`protobufjs`、`qs`、`lodash.*`。
- 能力：`Lark.WSClient`（长连接，`start({ eventDispatcher })`）、`Lark.EventDispatcher`（按事件名注册，`.register({'im.message.receive_v1': ...})`）、`Lark.Client`（全量 OpenAPI 封装）、Webhook 适配器（`adaptDefault` 等）。
- 官方文档写明 WS 连接在进程存活期间**自动重连**并抛 `reconnecting` / `reconnected` 事件。来源：[node-sdk docs/channel.md](https://github.com/larksuite/node-sdk/blob/main/docs/channel.md)。
- ⚠️ 社区报告（非官方结论）：SDK 心跳 ping 不校验 pong，NAT/防火墙静默断链时可能「连接看似 OPEN 但收不到消息」，需要自建活性检测。见 [issue #1370](https://github.com/hs3180/disclaude/issues/1370)。**设计按「SDK 重连不完全可信」处理。**

## 9. 凭据

- `tenant_access_token`：自建应用走 OAuth2 `client_credentials`（`POST /open-apis/auth/v3/tenant_access_token/internal`，body `app_id` / `app_secret`）；**当前为 JWT 格式，响应字段是 `access_token`**（勿读旧字段）；**有效期最长 2 小时**，以 `expires_in` 为准；剩余 < 30 分钟时调用会换发新 token。来源：[自建应用获取 tenant_access_token](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)（2026-10-14）。
- `App Secret` 属敏感信息，只能存服务端，不进日志、前端与客户端安装包。

## 10. 单聊 / 群聊差异

- 单聊：用户需在机器人**可用范围内**（否则 230013）、未屏蔽机器人（否则 230053）。
- 群聊：机器人必须**在群中且有发言权限**（否则 230002 / 230018）；群成员在群 `··· > 设置 > 群机器人 > 添加机器人`（官方注明电脑端添加）。
- **「@机器人才响应」由权限决定**：只申请 @ 系列权限 = 仅 @ 时推送；申请 `im:message.group_msg` = 群内所有消息都推。
- 外部群/外部用户单聊需开启「对外共享」能力并审核，仅企业自建应用。来源：[机器人支持外部群和外部用户单聊](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group)。

## 11. 身份与去重

- `user_id` = 租户内身份（跨应用一致，需字段权限）；`open_id` = 用户在**某个应用内**的身份（`ou_` 前缀，跨应用不同）；`union_id` = 同一开发商下统一身份。事件三者都带，发送均支持。来源：[用户身份概述](https://open.feishu.cn/document/platform-overveiw/basic-concepts/user-identity-introduction/introduction)。
- 入站去重：**用 `message_id`**（官方明确不要依赖 `event_id`）。
- 出站去重：`uuid` 参数（1 小时窗口）。

## 12. 「正在输入」

- **未查到官方「设置输入状态」的 API 文档**（社区有 `POST /messages/:message_id/typing` 的说法，官方文档未见，不采信）。
- 社区通行做法是在用户消息上加 **表情回应（reaction）**、完成后追加完成标记：`POST /open-apis/im/v1/messages/:message_id/reactions`。表情取值以官方[表情文案说明](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message-reaction/emojis-introduce)为准；2026-11-24 对照该页确认 **`Get`（已收到/已受理）、`Typing`、`DONE` 均为内置取值**（页面列举了对应 emoji_type 与图片）。本插件采用「收到打 `Get`、回答真正送达后追加 `DONE`、`Get` 不撤」——撤销是额外一次写调用且没有收益，保留 `Get` 在失败时仍表示「收到过」。
- **`DONE` 的打点时机（2026-11-25）**：不能打在 `receive()` 返回 accepted 时——核心的 accepted 只代表「校验通过、事件已发出、任务入队」（intake 的 `receiveOwnerMessage` emit 后立即返回），独立模式也是提交即返回，入队就打会让 `Get`/`DONE` 几乎同时落地、任务没完成却盖「已完成」。现在 `DONE` 只在回答真正送达时补：核心模式**直接读核心的 `Delivery.completes`**（`completionTargets()`，my-superagent#3：只有「该轮以 completed 结束 + 消息自己的 rpcId 在这轮里 + 这条交付送达」三条同时成立才带，停滞提醒/重启孤儿/派发回执/转投确认/命令回复都不带，取消/失败/审批被拒/超出 token 上限而中断的回合也不带——它们都没有正常答复；一条交付可完成多条消息，逐个打），独立模式在回合结束**回复真的发出去**之后按 `DoneAlign` 对齐补打；提醒作答（`/批准`、问题作答）只在**结算成功**时当场打——多题只答一半时提醒会回格式提示并继续挂起（`questions.ts` 的 `#noteGuidance`），那条消息不算处理完，不盖 `DONE`。此前按 `intent`/`refs`/标题猜的那套启发式已删除——实测它会误判：派发恢复告知与转投确认带 refs 却任务未完（误打），前台会话收尾不带 refs 却是正常回答（漏打）。旧核心不发 `completes` → 不打完成标记（漏打优于误打），不报错。桥还要把核心给的入站 `messageId` 翻成平台消息 id，这张映射表只留最近 500 条（有界，防常驻内存增长）：插件重启后，或一条消息在 500 条入站之后才被核心报完成，就翻不到、同样不打（只影响表情，不影响答案送达）。
- **独立模式的对齐规则（`done-align.ts`）**：不能按「一条 `turn/end` 结算一条」或「最近一条」猜——宿主 `queue`（`followup`）让排队消息独占自己的一轮，而 `steer`（默认）下回合进行中提交的消息被同一回合在步骤边界吸收、只发一次 `turn/end`。所以结算取队头 + 其后连续的 steer 条目；`/new`、`/sessions <序号>` 换绑定时整队清空（旧会话的 `turn/end` 会被会话校验丢弃，残留条目会被下一轮错认）。同一平台消息的 `DONE` 在 `stack` 层按消息 id 去重（桥、独立模式、提醒作答三条路共用这一个闭包），交付重投不会重复加。另：`DoneAlign` 的前提是「每个 turn/end 对应由队头那条开启的一轮」——宿主事件里没有可对账的 prompt id（`turn/start` 只有 `{turn}`、`user/message` 无 id），queue 模式下由 Web 端发起的回合会提前结算，影响限于完成表情。
- 结论：输入状态按 **best-effort 表情方案**设计，失败静默、面板可关，不写进任何协议能力声明。

## 14. 卡片回调（`card.action.trigger`）

- 事件由**长连接**推送（与消息事件同一个 WSClient），要求 **3 秒内**返回，否则平台按超时处理。来源：[卡片回调](https://open.feishu.cn/document/feishu-cards/card-callback-communication)。
- 回调体里有用的字段（本插件按此形状解析）：
  - `event.operator.open_id`：点按钮的人；
  - `event.action.value`：按钮 `behaviors[].value` 原样回传，**必须是对象**；
  - `event.action.option`：下拉/多选组件回传的选中值；
  - `event.action.form_value`：表单容器提交值（本期不用）；
  - `event.context.open_message_id` / `open_chat_id`：卡片所在消息与会话。
- 更新已发送的卡片走 `PATCH /open-apis/im/v1/messages/:message_id`，仅 `interactive` 类型、14 天内、单卡 5 QPS，卡片 `config.update_multi` 必须为 `true`（见 §5）。
- **待真机验证**：`multi_select_static` 的 `event.action.option` 是单个字符串、逗号串还是数组；本插件三种都解析，并把选项值写成序号避免文案里的逗号产生歧义。
- 审批类交互（`intent: 'approval'`）在 IM 侧**不作答**：卡片只展示，回调回 `not-allowed`，由 Web 端处理。
