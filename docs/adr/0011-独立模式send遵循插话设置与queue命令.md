# 0011 独立模式 /send 遵循插话设置与 /queue 固定排队

## 背景

0008 让 `/send` 固定用 `queue` 提交，面板的「回合内插话」只影响普通消息和发到当前会话的 `/send`。主人希望同一个开关覆盖所有发送，同时保留一个明确不打断目标回合的投递方式。

## 决策

- 「回合内插话」作用于独立模式的所有发送：普通消息、`/send` 到当前会话、`/send` 到其它会话。目标回合正在跑时，`steer` 插进当前回合，`queue` 排到下一轮。
- 新增 `/queue <序号、0 或会话 id> <内容>`，参数与 `/send` 相同，固定用 `queue`，不受面板设置影响。
- `/send` 与 `/queue` 共用会话定位、图片、回答观察与 `DONE` 对齐，只有提交模式不同。排队且目标正在跑时跳过上一轮的 `turn/end`；插话时当前 `turn/end` 就是这一条的回答。
- 排队一律按「先跳过目标当前那一轮」对齐（不看列表快照是否说在跑）：目标要么先发 `turn/start`，要么这一轮 `turn/end` 直接被跳过，快照过期也不会把别人的回答当成自己的。
- 当前绑定会话的「正在跑」以 `turn/start`/`turn/end` 维护的状态为准（比列表快照新）：排队消息在提交时已知目标在跑，就不随那一轮打 `DONE`，等它自己那轮结束再补。
- 面板提示写明 `/queue` 始终排队；两个命令在等回答时都拒绝同目标的第二条投递与 `/switch`。

## 后果

- 已知限制一：`steer` 的判断依赖提交前一刻的运行状态；列表说空闲、提交时目标已在跑（Web 端刚发起）时，这一条仍可能被并进别人的回合，回答与 `DONE` 归属只能靠事件顺序推断。宿主事件没有可对账的 prompt id（`turn/start` 只有 `{turn}`），这一层无法消除。
- 已知限制二：排队消息的 `waiting` 是提交前读到「正在跑」时打的一次性标记。若那一轮恰好在提交等待期间结束，标记会留到它自己那轮结束时才被清掉，表现为这条漏打 `DONE`（漏打优于误打）；根治可用事件里已有的 `turn` 号对账（`turn/start` 与 `turn/end` 的 data 都带 `turn`），当前实现未用。

- 默认 `steer` 下，`/send` 到正在跑的其它会话也会插话，可能改变目标当前回合；需要不打断时用 `/queue`。
- `/queue` 保留 0008 的固定排队语义；0008 关于序号快照、回答回收、超时的其余决定继续有效。
- 主人可以用命令显式选择是否排队，不必先改面板设置。

## 备选

- 保留 `/send` 固定 `queue`，只把设置扩到普通消息：不满足「所有发送」。
- 用 `/send --queue` 参数：与「第一个空白前是会话引用」的解析冲突，也不直观。
- 新增一个独立的 `/queue` 会话命令：参数与 `/send` 重复，未采用。
