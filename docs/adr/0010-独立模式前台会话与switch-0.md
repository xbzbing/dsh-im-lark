# 0010 独立模式的前台会话与 /switch 0

## 背景

0009 加了 `/switch`，但「最初绑定的会话」只是 `direct.json` 里的 `sessionId`，没有单独的名字。切到别的会话后，`/sessions` 会把原会话当成普通一行列出来；切回去后它仍是当前会话，列表里继续列着它自己，形成「回到前台再列会话，又看到前台」的套娃。另外也没有稳定的返回路径：只能从列表里按序号找，列表一变就找不到了。

## 决策

- 在 `direct.json` 里单独记前台：`frontSessionId` 与 `frontTitle`。旧版没有这两个字段时，未切换过的绑定按前台迁移；已经切走又没有前台记录的，`/switch 0` 明确说没有前台会话。
- 前台固定为序号 `0`，别名 `0` 与 `front`（大小写不敏感），`/switch` 与 `/send` 都认。`/sessions` 的快照和显示都排除前台，序号只对应其它会话，避免切回前台后列表里再套一个自己。
- `/switch 0`/`front` 回到前台时不写 `switched`，回复前缀随之消失；切到非前台会话才写 `switched: true`。`/new` 清掉绑定，也清掉前台。
- 切走期间收到前台会话的 `session/title` 时更新 `frontTitle`；回到前台时优先用列表里的最新标题，列表没给才用记住的标题。
- 换到其它会话（含回到前台）清空 `DoneAlign` 并复位运行态；切到当前会话不清。目标还有 `/send` 在等回答时拒绝切换，前台也一样。
- `DirectBindingStore` 的写入串行化：标题事件与 `/switch` 可能同一毫秒发生，不能让后写的旧绑定覆盖先写的新标题；临时文件名也加随机后缀，避免同毫秒 rename 互相踩。

## 后果

- 任何时候都能用 `/switch 0` 回到最初会话，不依赖 `/sessions` 快照是否还包含它。
- 前台不再出现在 `/sessions` 里，序号与切换目标一一对应；代价是不能用列表序号指前台，只能用 `0`/`front`。
- 前台会话被删掉后，`/switch 0` 与 `/send 0` 会明确提示，需要 `/new` 或先切到其它会话。
- 旧 `direct.json` 仍可读：未切换过的绑定自动补前台字段；已切换但没记前台的，升级后第一次 `/switch 0` 会提示没有前台，需要 `/new` 重新建一个；`/sessions` 只能换到其它会话，不会补前台。

## 备选

- 前台继续留在 `/sessions` 里，用 `*` 标出：切回前台后列表仍包含当前会话，序号和「当前」标记容易绕，未采用。
- 用 `/switch -1` 表示前台：负数不如 `0` 直观，也不方便和 `/send` 共用参数解析，未采用。
- 前台只放内存：重启后丢失，回到前台又得重新找，未采用。
