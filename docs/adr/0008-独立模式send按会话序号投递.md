# 0008 独立模式 /send 按会话序号投递

## 背景

独立模式最初的 `/send <文本>` 只是把文本回显到当前聊天，与核心模式的
`/send <序号或会话 id> <内容>` 同名不同义；`/sessions` 又用序号来切换绑定会话，
无法向其它会话发消息。主人要接着某个旧会话说话，只能先切换，回答也只会回到
切换后的绑定会话。

## 决策

- `/sessions [页码]` 只列会话（每页 10 个），每次列出一份新快照并落盘 `sessions.json`，
  序号在下次 `/sessions` 之前不变；不再切换绑定。
- `/send <序号或会话 id> <内容>` 用 `queue` 提交到目标会话，登记观察者等它 `turn/end`，
  把最后一条 assistant 文本发回发起命令的聊天；命令消息的 `DONE` 等回答真正送达后再补。
- 目标是当前绑定会话时走普通提交流程，不另开观察者，避免同一轮发两份回答。
- 目标会话正在跑时，先到的 `turn/end` 属于上一轮，跳过；30 分钟没结束就不再等并回一条提示。
- 序号快照按 `$DSH_HOME/.dsh-im-lark/` 下的私密文件保存（`sessions.json`）。

## 后果

- `/sessions <序号>` 不再切换会话；要接着某个旧会话说话用 `/send <序号> <内容>`。
- `/send` 从自测命令变成真正的跨会话投递；内容按原文提交，不再压平换行。
- `/stop` 仍只停当前绑定会话，不能停 `/send` 的目标会话；需要时再扩展。
- `/trace` 仍是「上一条回答的模型与耗时」，没有跟随核心的跟踪语义。

## 备选

- 保留回显、改名为 `/echo`：只能自测，不解决与核心同名不同义的问题。
- 只发不回收回答：与核心「结果回到这里」的语义不一致，主人还得去 Web 端看结果。
- 让 `/sessions <序号>` 同时切换并复用编号：一个参数两种含义，容易误操作，未采用。
