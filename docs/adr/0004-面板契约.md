# ADR-0004：面板用 Host RPC 信封 + `plugins.bundle.config` / `settings.section` 槽位

- 状态：已接受
- 日期：2026-11-19
- 修订：2026-11-20（传输改为 exact fetch 路由；补记设置侧栏入口）

## 背景

面板是两半式插件：`client.js` 由浏览器加载，`lib/index.js` 在 Host 进程里跑。浏览器
刷新就能拿到新的前端产物，Host 半却要重装才更新——两边字段一错位，页面就会拿
`undefined` 硬渲染，或者把旧请求发给新 Host。

面板还需要一条能读写状态的通道：连接状态、凭据保存、开关与阈值。宿主给插件的
连接面里，`connection.rpc.handle` 是**逻辑 socket 通道**，不走 HTTP；浏览器侧的
`connection.rpc.call` 则固定发 `POST /api/<通道名>`。两边对不上时页面只会看到
405，因此 Host 半必须注册 exact fetch 路由来接这个 POST。

## 决策

- Host 半用 `connection.fetch.register` 注册 `POST /api/dsh-im-lark`
  （`requestBody: 'buffered'`），自己解析宿主信封：
  请求 `{type:'client-request', rpcId, method, payload:{method, payload}}`，
  响应 `{type:'server-response', rpcId, result:{ok, value|error}}`。
  只接受 `application/json` 与 POST，其余回 405/415/400。
- 端点按用途分：`status`、`credentials.save`、`credentials.clear`、`probe`、
  `settings.set`、`reconnect`。
- 面板注册两个槽位：`plugins.bundle.config`（key 为包名，插件页配置节）与
  `settings.section`（设置侧栏的「飞书机器人」入口，order 25）；两处渲染同一个面板。
- 两半共享一个 `PANEL_CONTRACT` 常量；快照里带上它，对不上时页面只显示「重启」，
  不尝试兼容。
- 端点输入逐字段校验：类型、范围、白名单；不认识的字段与端点直接拒绝。内部错误
  只回一句「面板操作失败」，不把可能带路径的原始 message 透给页面。
- 凭据保存允许 Secret 留空：留空表示沿用已保存的那份，面板不回显密钥。
- 同路径路由在进程内唯一，状态挂在 `globalThis`：HMR 重叠期新实例只接管处理函数，
  摘路由交给最后卸下的实例；重复注册失败时降级为接管，不让插件加载失败。

## 后果

- 前后端契约是显式数字，升级时能看到、能测（单测断言两边常量相等）。
- 面板动作与轮询互不覆盖：动作失败只写自己的错误通道，轮询成功不清动作回执。
- 新增端点必须同时改两边并升契约版本；漏改会被类型检查与契约测试挡住。
- 面板不持有 Secret，只有 Host 的私密文件里有。
- 传输层依赖宿主 `connection.fetch`；CLI/桌面组合没有这个面时只记一条 warn，
  面板不可用但插件照常运行。

## 备选

- **`connection.rpc.handle` 逻辑通道**：只服务 socket 通道，浏览器 POST 过来是 405，
  不可用（曾按此实现并踩到）。
- **独立的 HTTP 路由**：要自己处理鉴权、信封与 CORS 语义；宿主已封装好的 fetch 面
  更省事，也和其它插件一致。
- **面板直接读文件**：浏览器拿不到 Host 的文件系统，只能经 RPC。
