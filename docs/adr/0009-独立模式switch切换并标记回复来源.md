# 0009 独立模式 /switch 切换会话并标记回复来源

## 背景

0008 把 `/sessions` 收成只读列表、`/send` 做跨会话投递后，独立模式没有「换一个
会话接着聊」的命令：每次都要 `/send <序号> <内容>`，回答虽然回到当前聊天，但下一句
又落回原来的绑定会话。主人同时跟进几个会话时，也看不出某条回答来自哪个会话。

## 决策

- `/switch <序号或会话 id>` 复用 `/sessions` 的快照与 `resolveSessionRef`，按序号或
  id 前缀换绑；序号仍只在下次 `/sessions` 时更新。
- 换绑到其它会话时清空 `DoneAlign`、复位运行态：旧会话的 `turn/end` 会被绑定校验
  丢弃，残留的待结算条目只会被新会话的回合错认。切到当前会话没有换绑，不清队列。
- 目标会话还有 `/send` 在等回答时拒绝切换，避免同一轮出现两条投递路径；目标已不在
  当前会话列表里时也拒绝，提示重新 `/sessions`。
- 换绑后，绑定会话路径的每条回复前加 `**会话名>**`；`/send` 的回答已有
  `来自会话「X」：`，不再重复加前缀。
- 标记以 `switched: true` 落盘在 `direct.json`，跨重启保留；`/new` 清除绑定即清除
  前缀。`session/title` 事件只在绑定仍指向该会话时更新标题，避免切走后改错名字。
- 标题压平空白、截断到 32 字符，并转义会打断 `**…**` 的 Markdown 字符；没有标题时
  用「未命名会话」。

## 后果

- `/sessions` 保持只读；切换是显式命令，不再靠序号命令兼做两件事。
- 前缀只影响发回飞书的显示，不写进会话内容，也不改变模型看到的输入。
- 宿主不推 `session/title` 时前缀可能停留在旧标题；标题缺失时显示「未命名会话」。
- `/switch` 只换绑定，不会停止旧会话正在跑的回合；旧回合的回答不再发到飞书，需要时
  到 Web 端查看。

## 备选

- 让 `/sessions <序号>` 同时切换：与 0008 的只读快照冲突，一个参数两种含义，未采用。
- 所有独立模式回复都加前缀（含 `/send` 回答）：与「来自会话」重复，也分不清回答归属，
  未采用。
- 前缀只放内存：重启后主人又失去会话标识，与「跨重启保留」的目标不符。
