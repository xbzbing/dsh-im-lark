# ADR-0002：独立模式与核心模式互斥，凭据就绪后再注册桥

- 状态：已接受
- 日期：2026-11-19

## 背景

插件有两种用法：不装核心时自己把消息交给 DSH 会话（独立模式）；装了
`dsh-my-superagent` 并把面板开关打开时，把消息、命令、提醒整体交给核心（核心模式）。

如果两条链路同时生效，同一句话会被处理两遍、回两遍；如果桥注册得太早，核心拿到的
是一个还不知道账号的空壳——桥的 `account` 只有读完凭据才知道。

判据还必须处理时序：核心可能在插件之后才启动，凭据也可能在面板上后填。

## 决策

- 模式判据只有一条：`service !== undefined && settings.superagent`。成立才注册桥、
  才把事件交给核心；否则事件走独立模式。
- 注册时机在**凭据就绪、整套连接对象建好之后**（`stack.ts` 建 `bridge`，入口拿到
  凭据变化回调后再 `bridges.register`）。
- 凭据变化时整套重建：先 `detach`（核心句柄 `dispose`，注册表摘掉 provider），
  再按新凭据建新桥、按当前模式重新注册。
- 设置变化只重算路由，不重建连接；已注册的桥不重复注册。
- 独立模式的消息去向由入站流水线兜底：`bridge.receive` 返回 `unknown`（没有核心
  句柄）时才转给独立会话；核心明确拒绝（非主人、已结算）不兜底。

## 后果

- 任何时刻只有一条链路在回话，消息不会重复处理。
- 面板开关切换立即生效，不需要重启。
- 桥的生命周期与连接上下文绑定；换 App 等于换桥，旧桥必须彻底释放。
- 独立模式依赖宿主的 `sessionController`；没有它的组合里独立模式不可用，
  消息会得到一句明确说明，而不是静默失败。

## 备选

- **先注册占位桥、拿到凭据后 `update(capabilities)`**：核心对 `account` 的校验在注册
  时发生，占位会失败或留下错误账号。
- **两种模式并存、按消息来源分流**：语义复杂，且用户无法预期哪条消息由谁处理。
