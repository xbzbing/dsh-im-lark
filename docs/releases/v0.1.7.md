## 主要变更

- **一次问多个问题，只发一张卡**：核心把一组题目发过来时，所有题目收进**同一张表单**，一个「提交」按钮一次答完，题目按 ①②③ 排开、题干加粗，无选项的题用输入框自由作答。此前每道题各占一排按钮，用户点完第一题就无处可点，一次提问要么答不完、要么只能到 Web 端处理。
- **答错了不用从头再来**：少答某一题、或单选题勾了多项时整单退回，卡片连同控件原地重画并指出是第几题，**已勾选与已填内容全部回填**，改完那一题再提交即可（飞书的表单提交是一次性的，只发一句提示会让卡片彻底点不动）。
- **单选「其他」与多选的自定义答案不再丢失**：单选同时勾了选项又填了「其他」时以「其他」为准；多选题允许勾选与「其他」并存，已作答卡把两段**都**显示出来——此前多选只显示勾选项，用户填的字在卡片上凭空消失。
- **修复**：作答被拒的提示改成用户能看懂的话（卡片失效、信息不完整、没收到表单），不再回「交付已不在内存里」这类内部说法；卡片装不下降级成纯文本卡片时不再重复标题。
- **内部**：降级文本与回执辅助拆到 `bridge-text.ts`（`bridge.ts` 回到 500 行以内），媒体类型 → 后缀合并到 `media.ts`；`maxQuestions` 直接复用卡片侧的 `MAX_ANSWER_QUESTIONS`，能力声明与实现不再各写一份 10。多题表单已通过真实租户验收，README 与设计文档同步。

## English

- **Several questions at once, still one card**: when the core sends a group of questions, every question lives in the **same form** and one submit button answers them all — laid out as ①②③ with bold headings, and questions without options take free text through an input. Previously each question took its own row of buttons, so answering the first one left nothing to click: a multi-question prompt either could not be finished in IM or had to be handed to the Web UI.
- **A rejected answer no longer costs the whole form**: a missing question or a multi-ticked single-select sends the submission back, re-renders the card with its controls in place and names the offending question, restoring **everything already checked and typed** so you only fix that one question (Feishu form submissions are one-shot; a text-only hint would leave the card dead).
- **Custom answers no longer disappear**: for a single-select, filling "other" now wins over the ticked option; for a multi-select, ticked options and "other" coexist and the answered card shows **both** — previously only the ticks were rendered and the text the user typed vanished from the card.
- **Fixes**: rejection messages are now written for humans (expired card, incomplete answer, missing form) instead of internal wording like "delivery is no longer in memory"; the plain-text fallback card no longer repeats the title.
- **Internal**: fallback text and receipt helpers moved to `bridge-text.ts` (`bridge.ts` is back under 500 lines), media type → extension merged into `media.ts`; `maxQuestions` reuses `MAX_ANSWER_QUESTIONS` so the capability claim and the card side cannot drift. The multi-question form has passed real-tenant verification, and the README plus design docs are updated accordingly.
