## 主要变更

- **飞书 / Lark 正式接入 DSH**：私聊机器人等于在 Web 端对话——收发文本、富文本、图片与文件，引用回复，`Typing`/`DONE` 处理反馈，长回答按字符与卡片体积双上限切段，流式回答原地更新同一张卡片。
- **两种互斥模式**：独立会话（插件自己建会话，内置 `/new` `/stop` `/sessions` `/trace` 等命令、问题与长任务提醒）与接入核心（飞书当作核心的入口，消息、命令、提醒整体交给 `my-superagent/v1`）。同一句话不会被两处处理。
- **交互卡片**：单题有选项的提问发飞书交互卡片——每项一个勾选器、可填「其他」、必须点「提交」才生效；飞书没有单选按钮组，单选靠卡片文案区分，提交后在服务端强制单选。多问题、审批与卡片超限仍走文字并给格式引导。独立模式与核心模式都在真实租户验收。
- **面板**：Web 端插件页扫码一键创建应用，或手动填 App ID / App Secret；看连接状态、开关收发与核心接入、改消息行为；独立模式可调回合内插话、会话工作区与提醒。
- **内部**：测试自包含（不依赖私有核心，公开 CI 跑的就是全量）；发布走 `.github/workflows/release.yml`——门禁与发布分成两个 job、npm 用 OIDC 可信发布并附 provenance、预发布只进频道标签。

## English

- **Feishu / Lark joins DSH**: a private chat with the bot is a Web-side conversation — text, rich text, images and files in both directions, quoted replies, `Typing`/`DONE` processing feedback, long answers split under both character and card-size limits, streamed answers updating the same card in place.
- **Two mutually exclusive modes**: standalone (the plugin runs the session itself, with `/new` `/stop` `/sessions` `/trace`, question and long-task reminders) and core-attached (Feishu becomes one entry point of the core; messages, commands and reminders all go to `my-superagent/v1`). A single message is never handled twice.
- **Interactive cards**: a single-choice or multi-choice question is rendered as a Feishu card — one checker per option, an optional "other" input, and a submit button; Feishu has no radio group, so single-select is stated in the card text and enforced server-side. Multi-question interactions, approvals and oversized cards fall back to text with format guidance. Both modes were accepted against a real tenant.
- **Panel**: scan to create the app, or fill App ID / App Secret by hand; see connection state, toggle send/receive and core attachment, tune message behaviour; in standalone mode also steer, workspace and reminders.
- **Internal**: tests are self-contained (no private core; public CI runs the full suite); releases go through `.github/workflows/release.yml` — gate and release in separate jobs, npm trusted publishing with provenance, prereleases published to channel dist-tags only.
