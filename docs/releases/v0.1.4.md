## 主要变更

- **完成标记改读核心的权威信号**：`DONE` 不再靠 intent、refs 或标题猜，只认核心的 `Delivery.completes`（`owner-message-completion`）：该轮正常收尾、消息本身由这一轮回答、交付确实送达，三条同时成立才补打。派发回执、停滞提醒、转投确认不再误打，前台直接回答也不再漏打；取消、失败、审批被拒、超出 token 上限而中断的回合不打（它们没有正常答复）；旧核心不带这个字段时不补，漏打优于误打。
- **修复**：流式回答的卡片超过 28 KB 改成分条发送后，最终稿不再被吞掉——此前只发出中间进度，最后一段答案会丢；现在终稿照常发送，并且只补一次 `DONE`。
- **中英双语文档**：新增 [README.en.md](../../README.en.md) 与两张浅色 hero 图，README 顶部可直接切换语言；中文版 hero 随 npm 包一起发布，npm 页面不再只有纯文字。
- **内部**：提醒作答改为「已结算 / 未结算」三态认领，多题只答一半不再盖 `DONE`；同一消息的 `DONE` 统一在栈层按消息 id 去重，交付重投不会重复打；补上 `completes` 的负向用例（回执、停滞、孤儿、转投、取消轮）与「入站映射只留最近 500 条」的边界说明。

## English

- **Completion is now driven by the core's authoritative signal**: `DONE` is no longer guessed from intent, refs or titles; it follows the core's `Delivery.completes` (`owner-message-completion`) and is added only when the round ended normally, the message itself was answered by that round, and the delivery was actually sent. Dispatch receipts, stall notices and transfer confirmations no longer get a false `DONE`, while a direct answer from the Web UI no longer misses it; cancelled, failed, approval-rejected or token-limit-truncated rounds get none (they have no normal answer); older cores that do not send the field get none either — a missed mark beats a wrong one.
- **Fixes**: when a streaming answer's card exceeds 28 KB and switches to split messages, the final revision is no longer swallowed — previously only intermediate progress was sent and the last part of the answer was lost; the final revision is now delivered and `DONE` is added exactly once.
- **Bilingual docs**: added [README.en.md](../../README.en.md) plus two light hero images, with a language switch at the top of the README; the Chinese hero ships with the npm package, so the npm page is no longer text-only.
- **Internal**: reminder answers use a three-state claim (`settled` / `unsettled`), so a partially answered multi-question prompt no longer gets a `DONE`; `DONE` is deduplicated by message id in the stack layer, so delivery retries never double-mark; added negative cases for `completes` (receipts, stalls, orphans, transfers, cancelled rounds) and documented the 500-entry bound of the inbound id map.
