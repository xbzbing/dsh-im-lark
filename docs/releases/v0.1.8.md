## 主要变更

- **引用回复的卡片不再重复「参考」段**：交付卡正文末尾原本总会列一遍会话（比如「参考：- 当前目录 C:\…」）。现在只要这条消息真的以**引用回复**发出、引用气泡已经把原消息标出来，卡片就不再重复这段；主动推送（长任务完成、周报、分析）以及插件重启后没带上引用气泡的消息仍然保留——那时它是定位会话的唯一线索。
- **内部**：裁剪做在渲染用的交付副本上（`presented`），流式 PATCH、作答终态、重试、过期替代都沿用首屏那份，参考段不会中途冒出来；判据是「引用回复解析成功」而不是「带 `inReplyTo` 字段」，设计文档 §6.3 记下了这条与理由。

## English

- **Quoted replies no longer repeat the "reference" block**: delivery cards used to always end with the session list (for example "参考：- 当前目录 C:\…"). When a message really goes out as a **quoted reply** and the quote bubble already marks the original message, the card no longer repeats it. Proactive pushes (long-task completion, weekly report, analysis) and messages whose quote could not be resolved keep it — in those cases it is the only way to tell which session a message belongs to.
- **Internal**: the trimming happens on the delivery copy used for rendering (`presented`), so stream PATCHes, answered/rejected/retried and superseded redraws reuse what the first render decided and the block cannot reappear later; the trigger is "the quoted reply resolved", not "an `inReplyTo` field exists", and design doc §6.3 records the rule and its reason.
