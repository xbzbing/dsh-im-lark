## 主要变更

- **修复：卡片作答被拒后不再「点了没反应」**。核心模式下作答被拒时，原先只写插件调试日志，用户侧看不到任何反馈；现在每次拒绝都会**整卡重画**——保留勾选框与提交按钮、把原因写在卡上（如「单选题只能勾一项」），可以直接改了再提交。已经不能再答的卡（重启丢了记录、已过期）改成失效态、去掉勾选框并写清原因。独立模式的提醒卡同步改成重画。
- **修复：改选项重新提交不再被当成平台重推丢掉**。入站去重原先只看按钮的 `value`，而同一张卡每次提交的 `value` 完全相同（勾选值在 `form_value` 里），于是「勾两项被拒 → 改勾一项再提交」的第二次回调被直接丢弃。现在去重键带上表单值与选项，同一份回调仍只在 5 秒重推窗口内处理一次。
- **内部**：新增 7 个单测覆盖这两条路径（拒绝后重画、改选项重提交、重推窗口去重）；ADR-0005 记下两条根因与实测结论。

## English

- **Fixed: a rejected card answer no longer looks like "nothing happened"**. In core mode a rejection used to go only to the plugin's debug log. Now every rejection **re-renders the whole card** — checkers and the submit button stay, the reason is written on the card (e.g. "single choice takes exactly one option"), and the owner can adjust and submit again. Cards that can no longer be answered (records lost on restart, expired) become a terminal state with the checkers removed and the reason stated. Standalone reminder cards re-render the same way.
- **Fixed: re-submitting with a different selection is no longer dropped as a platform retry**. Inbound dedupe used the button `value` only, and that value is identical on every submission of the same card (the selection lives in `form_value`), so the second callback — "two checked, rejected, then one checked" — was discarded. The dedupe key now includes the form values and option, while an identical callback is still processed only once inside a 5-second retry window.
- **Internal**: 7 new unit tests cover both paths (re-render on rejection, re-submit with a different selection, dedupe inside the retry window); ADR-0005 records both root causes and the on-device findings.
