## 主要变更

- **处理反馈调整**：收到消息后先打 `Get`（官方表情文案说明里「已收到/已受理」语义的取值，橙色 GET 徽标），处理完成后**追加** `DONE`（显示「完成」）——两个标记并排留在消息上，`Get` 永不撤销。处理失败时保留 `Get`（只表示「收到过」）、不追加 `DONE`，不给「已完成」的假信号。
- **少一次写调用**：流水线不再需要 `removeReaction`，表情相关只增不减；`LarkApi` 端口仍保留该能力。
- **文档核对**：对照官方[表情文案说明](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message-reaction/emojis-introduce)确认 `Get` / `Typing` / `DONE` 均为内置 `emoji_type`，协议事实文档中「待真机验证」项关闭；README、AGENTS.md、设计文档与面板提示语同步新口径。

## English

- **Processing feedback reworked**: on arrival the bot adds a `Get` reaction (the "received / acknowledged" emoji from the official emoji list, an orange GET badge), and appends `DONE` when processing finishes — both reactions stay side by side on the message and `Get` is never removed. On failure `Get` stays (it only means "received") and no `DONE` is added, so a failed run never shows a fake "completed" signal.
- **One less write**: the pipeline no longer calls `removeReaction`; reactions are add-only. The `LarkApi` port still exposes the capability.
- **Documentation check**: `Get` / `Typing` / `DONE` were confirmed as built-in `emoji_type` values against the official [emoji reference](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message-reaction/emojis-introduce), closing the "needs real-device verification" item in the platform-facts doc; README, AGENTS.md, the design doc and the panel hint now use the new wording.
